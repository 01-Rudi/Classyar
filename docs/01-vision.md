## ۱. مقدمه

### ۱.۱ هدف سند
این سند چشم‌انداز، دامنه و ذی‌نفعان پروژهٔ **کلاس‌یار** را تعریف می‌کند.
هدف آن ایجاد یک درک مشترک میان تیم توسعه، کاربران و ذی‌نفعان درباره
«چه چیزی می‌سازیم، برای چه کسی، و چرا» است.

این سند **قرارداد رسمی** نیست، بلکه **مرجع راهنما** برای تصمیم‌گیری‌های
بعدی در طول چرخهٔ حیات پروژه است و در هر Sprint بازبینی می‌شود.

### ۱.۲ دامنهٔ سند
- **در دامنه:** اهداف محصول، کاربران هدف، محدودهٔ MVP، معیارهای موفقیت،
ریسک‌های سطح بالا.
- **خارج از دامنه:** جزئیات فنی، طراحی UI، نیازمندی‌های دقیق functional (که
در SRS می‌آید).

## ۲. چشم‌انداز محصول

### ۲.۱ بیانیهٔ چشم‌انداز (Vision Statement)

> **برای** دانشجویانی **که** برای پیدا کردن جزوه، نمونه‌سؤال و اطلاعات مطمئن
> دربارهٔ استادان خود بین گروه‌های پیام‌رسان و فایل‌های پراکنده سرگردان‌اند،
> **کلاس‌یار** یک **پلتفرم وب دانشجویی** است
> **که** اشتراک جزوه، جست‌وجو بر پایهٔ استاد، استان و واحد دانشگاهی،
> امتیازدهی و گفت‌وگو را در یک جا فراهم می‌کند.
>
> **برخلاف** گروه‌های تلگرام و ایتا که محتوا در آن‌ها گم می‌شود و کیفیتش
> مشخص نیست، **محصول ما** محتوا را بر پایهٔ استاد و درس سازمان می‌دهد و با
> امتیاز دانشجویان و تأیید استادان قابل‌اعتماد می‌کند.

### ۲.۲ ارزش پیشنهادی (Value Proposition)

| برای | ارزش |
|------|-------|
| **دانشجوی استفاده‌کننده** | پیدا کردن سریع جزوه و نمونه‌سؤال استاد موردنظر، با دیدن امتیاز و نظر دیگران قبل از دانلود |
| **دانشجوی مشارکت‌کننده** | اشتراک جزوه، دریافت بازخورد و امکان گرفتن نمرهٔ تشویقی از استاد |
| **استاد** | دیدن منابع دانشجویی مربوط به درس خود، تأیید جزوه‌های خوب و تشویق مشارکت‌کنندگان |
| **مدیر سامانه** | کنترل محتوا و کاربران و حفظ اعتبار پلتفرم |

### ۲.۳ مزیت رقابتی
- تمرکز: همه‌چیز بر پایهٔ «استاد + درس + واحد دانشگاهی» سازمان می‌یابد، نه یک انبار فایل
- اعتماد: امتیاز دانشجویان و تأیید استاد، کیفیت جزوه را نشان می‌دهد
- انگیزه: استاد می‌تواند برای مشارکت مفید نمرهٔ تشویقی در نظر بگیرد
- ارتباط: نظرها، لینک گروه‌های کلاسی و نمونه‌سؤال‌ها در کنار هم هستند
- سادگی: فارسی، راست‌به‌چپ و بدون پیچیدگی

## ۳. مشکل و فرصت

### ۳.۱ مشکل فعلی (Problem Statement)
دانشجویان و استادان با چالش‌های زیر روبه‌رو هستند:
1. **پراکندگی منابع:** جزوه و نمونه‌سؤال در گروه‌های پیام‌رسان و حافظهٔ شخصی افراد پخش است.
2. **سخت‌بودن پیدا کردن:** نمی‌توان جزوهٔ یک استاد مشخص در یک واحد دانشگاهی مشخص را فیلتر کرد.
3. **نبود معیار کیفیت:** دانشجو نمی‌داند کدام جزوه کامل و قابل‌اعتماد است.
4. **نبود اطلاعات دربارهٔ استاد:** نظر و تجربهٔ دانشجویان قبلی در دسترس نیست.
5. **نبود انگیزه برای اشتراک:** دانشجویی که جزوهٔ کامل دارد دلیلی برای به‌اشتراک‌گذاشتن آن ندارد.
6. **نبود ارتباط استاد با منابع دانشجویی:** استاد نمی‌داند دانشجویان از چه منابعی استفاده می‌کنند.

### ۳.۲ فرصت (Opportunity)
- نیاز مشترک میان دانشجویان همهٔ دانشگاه‌ها و رشته‌ها
- امکان ساخت یک مخزن مشترک و قابل‌جست‌وجو از جزوه‌های واقعی
- امکان ایجاد انگیزه با نمرهٔ تشویقی و امتیازدهی
- ضعف گروه‌های پیام‌رسان در سازمان‌دهی محتوا
- امکان توسعه به همهٔ استان‌ها و دانشگاه‌های کشور

## ۵. محدودهٔ محصول

### ۵.۱ داخل محدوده (In Scope — MVP)

**کاربری (Functional):**
- **F-01** ثبت‌نام و ورود با نقش دانشجو یا استاد
- **F-02** مدیریت اطلاعات پایه (استان، دانشگاه، واحد، درس، استاد) توسط مدیر؛ دانشجو می‌تواند افزودن استاد را درخواست دهد
- **F-03** آپلود جزوه با مشخصات (استاد، درس، استان، واحد، ترم، توضیح)
- **F-04** جست‌وجو و فیلتر بر پایهٔ استاد، استان، واحد دانشگاهی، درس و ترم
- **F-05** صفحهٔ جزئیات جزوه و دانلود فایل
- **F-06** امتیازدهی ۱ تا ۵ به جزوه و نمایش میانگین
- **F-07** صفحهٔ استاد: جزوه‌ها، نمونه‌سؤال‌ها، لینک گروه‌ها و میانگین امتیاز
- **F-08** امتیازدهی دانشجو به استاد
- **F-09** نظرها روی جزوه و صفحهٔ استاد، همراه با امکان پاسخ
- **F-10** ثبت و نمایش لینک گروه‌های کلاسی و نمونه‌سؤال‌ها
- **F-11** تأیید جزوه و ثبت نمرهٔ تشویقی توسط استاد
- **F-12** گزارش محتوای نامناسب یا ناقض حقوق دیگران
- **F-13** پنل مدیر: کاربران، گزارش‌ها و حذف محتوا

**غیرکاربری (Non-functional):**
- **NF-01** زمان بارگذاری صفحه < ۲ ثانیه
- **NF-02** پشتیبانی از ۱۰۰ کاربر همزمان
- **NF-03** رابط کاربری واکنش‌گرا (Responsive) برای موبایل و دسکتاپ
- **NF-04** رمزنگاری گذرواژه‌ها (bcrypt)
- **NF-05** پشتیبانی از زبان فارسی و RTL
- **NF-06** اعتبارسنجی فایل‌ها (فقط PDF، JPG، PNG و DOCX، حداکثر ۲۰ مگابایت)
- **NF-07** کنترل دسترسی بر پایهٔ نقش (دانشجو، استاد، مدیر)
- **NF-08** هر کاربر برای هر جزوه و هر استاد فقط یک امتیاز بتواند ثبت کند

### ۵.۲ خارج از محدوده (Out of Scope)

| مورد | دلیل |
|------|-------|
| ثبت نمرهٔ رسمی در سامانهٔ دانشگاه | نمرهٔ تشویقی فقط در کلاس‌یار ثبت می‌شود و اتصال به سامانهٔ آموزشی خارج از توان یک ترم است |
| اپلیکیشن موبایل | تمرکز روی وب |
| چت زنده بین کاربران | نظرها و پاسخ‌ها کافی است |
| فروش جزوه و پرداخت | خارج از هدف پروژه |
| تشخیص خودکار سرقت یا کپی‌رایت | پیچیدگی فنی؛ فقط گزارش دستی |
| تبدیل جزوهٔ دست‌نویس به متن (OCR) | خارج از توان یک ترم |
| احراز هویت با سامانهٔ دانشگاه | نیاز به مجوز؛ فقط ایمیل و تأیید دستی استاد |
| چند زبانه (فارسی/انگلیسی) | تمرکز روی فارسی |

### ۵.۳ محدودیت‌ها (Constraints)
- **زمانی:** ۱۴ هفته، ۳ Sprint
- **تیمی:** ۳-۵ نفر
- **فنی:** بدون سرور اختصاصی، استقرار روی سرویس ابری رایگان
- **بودجه:** صفر (فقط ابزارهای رایگان)
- **محتوایی:** مسئولیت محتوای بارگذاری‌شده با کاربر است و باید قوانین استفاده تعریف شود

## ۸. رویکرد و متدولوژی

### ۸.۱ متدولوژی
- **Scrum سبک‌شده:** ۳ Sprint دو-سه هفته‌ای
- **ابزار مدیریت:** GitHub Projects
- **جلسات:** Sprint Planning، Daily (کوتاه، آنلاین)، Review، Retrospective

### ۸.۲ فناوری پیشنهادی
| لایه | فناوری |
|------|--------|
| Backend | Node.js + Express |
| Frontend | React |
| Database | PostgreSQL |
| ORM | Prisma |
| ذخیرهٔ فایل | دیسک سرور یا سرویس ذخیرهٔ ابری رایگان |
| Version Control | Git + GitHub |
| CI/CD | GitHub Actions |
| مستندسازی | Markdown در GitHub |

> دلیل انتخاب: یک زبان (JavaScript) برای کل تیم، ابزارهای رایگان و مستندات فراوان،
> و پایگاه دادهٔ رابطه‌ای برای ارتباط‌های استاد، درس، واحد و جزوه.

### ۸.۳ Definition of Done
یک Story وقتی «تمام» است که:
1. کد نوشته و Merge شده باشد.
2. تست Unit برای آن نوشته شده باشد.
3. Code Review شده باشد.
4. مستندات مربوطه به‌روز شده باشد.
5. در محیط Demo کار کند.
