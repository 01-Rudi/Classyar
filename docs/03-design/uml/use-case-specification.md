# Use Case Specification — کلاس‌یار

| | |
|---|---|
| **نام پروژه** | کلاس‌یار (ClassYar) |
| **نسخهٔ سند** | ۱.۰ |
| **تاریخ** | ۱۴۰۵/۰۸/۰۲ |
| **وضعیت** | پیش‌نویس |
| **مرجع** | `use-case.md` و `docs/02-requirements/user-stories.md` |

این سند مشخصات هفت Use Case مهم را می‌نویسد؛ بقیه در Sprintهای بعد کامل می‌شوند.
هر Use Case به User Story و معیار پذیرش خودش وصل است.

---

## UC-01: ثبت‌نام و ورود

| بخش | توضیح |
|------|-------|
| **User Story** | US-01 |
| **Actor** | مهمان |
| **Precondition** | کاربر وارد حساب نشده است |
| **Main Flow** | ۱. کاربر ایمیل، گذرواژه و نقش (دانشجو یا استاد) را وارد می‌کند<br>۲. سیستم ورودی‌ها را اعتبارسنجی می‌کند<br>۳. سیستم حساب را می‌سازد و گذرواژه را با bcrypt ذخیره می‌کند<br>۴. کاربر وارد می‌شود و به صفحهٔ اصلی می‌رود |
| **Alternative** | ایمیل تکراری یا گذرواژهٔ کمتر از ۸ کاراکتر ← پیام خطا<br>نقش استاد ← حساب تا تأیید مدیر غیرفعال می‌ماند |
| **Postcondition** | حساب ساخته شد و کاربر وارد شده است (یا منتظر تأیید مدیر است) |

## UC-03: جست‌وجو و فیلتر جزوه‌ها

| بخش | توضیح |
|------|-------|
| **User Story** | US-07 |
| **Actor** | مهمان، دانشجو |
| **Precondition** | حداقل یک جزوه ثبت شده است |
| **Main Flow** | ۱. کاربر یک یا چند فیلتر (استاد، استان، واحد، درس، ترم) را انتخاب می‌کند<br>۲. سیستم جزوه‌های مطابق را می‌خواند<br>۳. فهرست را با امتیاز و استاد نمایش می‌دهد (کمتر از ۲ ثانیه) |
| **Alternative** | نتیجه‌ای نبود ← پیام «جزوه‌ای یافت نشد»<br>پاک‌کردن فیلترها ← فهرست کامل |
| **Postcondition** | فهرست فیلترشده نمایش داده شد |

## UC-05: آپلود جزوه

| بخش | توضیح |
|------|-------|
| **User Story** | US-03 |
| **Actor** | دانشجو |
| **Precondition** | دانشجو وارد حساب شده است |
| **Main Flow** | ۱. دانشجو فرم آپلود را باز می‌کند<br>۲. استاد، درس، استان، واحد و ترم را انتخاب و فایل را برمی‌گزیند (توضیح اختیاری)<br>۳. سیستم نوع و حجم فایل را بررسی می‌کند<br>۴. سیستم فایل و مشخصات را ذخیره می‌کند<br>۵. جزوه در فهرست «جزوه‌های من» نمایش داده می‌شود |
| **Alternative** | فایل غیر از PDF، JPG، PNG و DOCX یا بیش از ۲۰ مگابایت ← پیام خطا<br>فیلد اجباری خالی ← پیام خطا |
| **Postcondition** | جزوه ثبت شد و برای دیگران قابل جست‌وجو است |

## UC-07: امتیازدادن به جزوه

| بخش | توضیح |
|------|-------|
| **User Story** | US-08 |
| **Actor** | دانشجو |
| **Precondition** | دانشجو وارد حساب شده و صفحهٔ جزوه را باز کرده است |
| **Main Flow** | ۱. دانشجو امتیاز ۱ تا ۵ را انتخاب می‌کند<br>۲. سیستم بررسی می‌کند قبلاً امتیاز نداده باشد<br>۳. امتیاز ذخیره و میانگین بلافاصله به‌روز می‌شود |
| **Alternative** | امتیاز قبلی دارد ← سیستم همان را ویرایش می‌کند (یک امتیاز برای هر کاربر)<br>خارج از ۱ تا ۵ ← پیام خطا |
| **Postcondition** | میانگین امتیاز جزوه به‌روز شد |

## UC-13: تأیید جزوه و ثبت نمرهٔ تشویقی

| بخش | توضیح |
|------|-------|
| **User Story** | US-13 |
| **Actor** | استاد |
| **Precondition** | حساب استاد توسط مدیر فعال شده و وارد شده است |
| **Main Flow** | ۱. استاد فهرست جزوه‌های مربوط به درس خودش را می‌بیند<br>۲. یک جزوه را بررسی و تأیید می‌کند<br>۳. نمرهٔ تشویقی را با یادداشت کوتاه ثبت می‌کند<br>۴. جزوه نشان «تأیید استاد» می‌گیرد<br>۵. آپلودکننده نمره را در پروفایلش می‌بیند |
| **Alternative** | جزوه مربوط به استاد دیگری است ← دسترسی رد می‌شود<br>جزوه را تأیید نکند ← بدون نشان می‌ماند |
| **Postcondition** | جزوه تأیید و نمرهٔ تشویقی ثبت شد؛ سامانه نشان می‌دهد این نمره رسمی نیست |

## UC-14: گزارش محتوای نامناسب

| بخش | توضیح |
|------|-------|
| **User Story** | US-14 |
| **Actor** | دانشجو، استاد |
| **Precondition** | کاربر وارد حساب شده و یک جزوه یا نظر را می‌بیند |
| **Main Flow** | ۱. کاربر دکمهٔ «گزارش» را می‌زند<br>۲. دلیل را می‌نویسد یا انتخاب می‌کند<br>۳. سیستم گزارش را با وضعیت «جدید» ثبت می‌کند |
| **Alternative** | همین محتوا را قبلاً گزارش کرده ← پیام «قبلاً گزارش شده» |
| **Postcondition** | گزارش برای مدیر ثبت شد |

---

## UC-15: بررسی گزارش‌ها و حذف محتوا

| بخش | توضیح |
|------|-------|
| **User Story** | US-15 |
| **Actor** | مدیر سامانه |
| **Precondition** | مدیر وارد پنل شده است |
| **Main Flow** | ۱. مدیر فهرست گزارش‌ها را با وضعیت می‌بیند<br>۲. یک گزارش را باز و محتوا را بررسی می‌کند<br>۳. محتوا را حذف می‌کند<br>۴. وضعیت گزارش «بررسی‌شده» می‌شود |
| **Alternative** | گزارش بی‌اساس است ← مدیر آن را رد می‌کند و وضعیت «ردشده» می‌شود<br>کاربر خاطی ← مدیر می‌تواند حسابش را مسدود کند |
| **Postcondition** | گزارش بسته و محتوای نامناسب حذف شد |
