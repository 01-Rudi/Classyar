# تمرین مدل‌سازی ایستا و پویا — کلاس‌یار

> این مستند یک تمرین درسی است و به‌صورت جداگانه، در حوزهٔ موضوع پروژهٔ کلاس‌یار (پلتفرم اشتراک جزوه و نمونه‌سؤال) انجام شده است.

## ۱. هدف

هدف این تمرین، شناخت تفاوت مدل‌های ایستا (Static / Structural) و پویا (Dynamic / Behavioral) و نمایش هرکدام روی یک نمونهٔ واقعی است:

- مدل ایستا: نمودار کلاس، برای نمایش ساختار داده‌ها و روابط آن‌ها
- مدل پویا: نمودار توالی، برای نمایش ترتیب تعامل اجزا در سناریوی بارگذاری جزوه

|---|---|---|

مدل‌سازی ایستا و پویا در فاز Modeling (تحلیل و طراحی) انجام می‌شود.

## ۳. مدل ایستا در برابر مدل پویا

| ویژگی | ایستا (Structural) | پویا (Behavioral) |
|---|---|---|
| پرسش اصلی | سیستم از چه چیزهایی ساخته شده است؟ | سیستم چگونه کار می‌کند؟ |
| وابستگی به زمان | مستقل از زمان و ترتیب | وابسته به ترتیب و زمان |
| نمودارهای رایج | کلاس، شیء، مؤلفه، استقرار | توالی، موردکاربرد، فعالیت، حالت |
| نمونه در کلاس‌یار | ارتباط جزوه با استاد، درس و نیم‌سال | مراحل بارگذاری جزوه |

این دو مدل مکمل یکدیگرند: مدل ایستا «چه چیزی» را نشان می‌دهد و مدل پویا «چگونه» را.

## ۴. مدل ایستا — نمودار کلاس

### ۴.۱ نمودار روابط

    User 1 -------------> 0..* Note          (uploads)
    Professor 1 --------> 0..* Note          (related to)
    Course 1 -----------> 0..* Note          (contains)
    UniversityUnit 1 ---> 0..* Note          (associated with)
    Semester 1 ---------> 0..* Note          (belongs to)
    User 1 -------------> 0..* NoteRating    (submits)
    Note 1 -------------> 0..* NoteRating    (receives)
    User 1 -------------> 0..* Comment       (writes)
    Note 1 -------------> 0..* Comment       (receives)
    Comment 0..1 -------> 0..* Comment       (replies to)

### ۴.۲ کلاس‌ها و ویژگی‌ها

| کلاس | ویژگی‌ها | نقش |
|---|---|---|
| User | id, fullName, email, role | کاربران سامانه (دانشجو، استاد، مدیر) |
| Professor | id, fullName, academicTitle | اطلاعات استادان |
| UniversityUnit | id, name, province | واحد دانشگاهی و استان آن |
| Course | id, title, courseCode | درس دانشگاهی |
| Semester | id, title, year | نیم‌سال تحصیلی |
| Note | id, title, description, filePath, uploadedAt, status | جزوه یا نمونه‌سؤال |
| NoteRating | id, score, createdAt | امتیاز یک کاربر به یک جزوه |
| Comment | id, content, createdAt | نظر کاربران و پاسخ به نظر |

### ۴.۳ توضیح روابط

| رابطه | چندی (Multiplicity) | معنا |
|---|---|---|
| User ← Note | ۱ به ۰..* | هر کاربر چند جزوه بارگذاری می‌کند؛ هر جزوه یک بارگذار دارد |
| Professor ← Note | ۱ به ۰..* | هر جزوه به یک استاد مربوط است |
| Course ← Note | ۱ به ۰..* | هر جزوه به یک درس مربوط است |
| UniversityUnit ← Note | ۱ به ۰..* | هر جزوه به یک واحد دانشگاهی مربوط است |
| Semester ← Note | ۱ به ۰..* | هر جزوه به یک نیم‌سال مربوط است |
| User ← NoteRating | ۱ به ۰..* | هر کاربر می‌تواند چند امتیاز ثبت کند |
| Note ← NoteRating | ۱ به ۰..* | هر جزوه می‌تواند چند امتیاز بگیرد |
| User ← Comment | ۱ به ۰..* | هر کاربر چند نظر می‌نویسد |
| Note ← Comment | ۱ به ۰..* | هر جزوه چند نظر دارد |
| Comment ← Comment | ۰..۱ به ۰..* | رابطهٔ بازگشتی؛ یک نظر می‌تواند پاسخی به نظر دیگر باشد |

## ۶. مقایسهٔ دو مدل در این تمرین

| معیار | نمودار کلاس | نمودار توالی |
|---|---|---|
| نوع مدل | ایستا (ساختاری) | پویا (رفتاری) |
| نشان می‌دهد | کلاس‌ها، ویژگی‌ها و روابط | ترتیب پیام‌ها بین اجزا |
| کاربرد در طراحی | مبنای طراحی پایگاه داده | مبنای طراحی منطق سرور و رابط کاربری |
| مثال در این مستند | ارتباط Note با Course و Professor | مراحل بارگذاری جزوه |

## ۷. محدودیت‌ها و نکات بهبود

- در نمودار توالی، احراز هویت (ورود کاربر) نشان داده نشده است.
- خطای ذخیره‌سازی فایل یا ثبت در پایگاه داده مدل نشده است. مثلاً اگر فایل ذخیره شود ولی ثبت در پایگاه داده شکست بخورد، باید فایل حذف شود.
- نقش مدیر و فرایند تأیید جزوه مدل نشده است.
- کلاس‌هایی برای درخواست افزودن استاد و امتیازدهی به استاد می‌توانند در ادامه اضافه شوند.
- ویژگی‌هایی مانند رمز عبور (به‌صورت هش) برای User و نوع محتوا (جزوه یا نمونه‌سؤال) برای Note در این مدل ساده‌شده نیامده‌اند.
- متدها (عملیات) کلاس‌ها نشان داده نشده‌اند و فقط ویژگی‌ها آمده‌اند.
- این مدل مفهومی است و هنگام پیاده‌سازی باید با مدل واقعی پایگاه داده هماهنگ شود.

## ۸. نتیجه‌گیری

نمودار کلاس ساختار ایستای کلاس‌یار و ارتباط موجودیت‌ها را نشان می‌دهد و نمودار توالی رفتار پویای سامانه را در سناریوی بارگذاری جزوه. استفاده از هر دو مدل، دید کامل‌تری برای طراحی پایگاه داده و پیاده‌سازی فراهم می‌کند.
